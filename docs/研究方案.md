# 研究方案

## 实现顺序

```
基线 T1-T5 已完成（根因已确认，详见 [[研究方案]]）
  → 三轮迭代：③ 系统记忆 → ④ 24h 时间 → ⑤ 健康系统
    → 每轮跑 T3 规模验证（3ag × 10wk，约 4h）
      → T6 全组合（③+④+⑤ 全启用，5ag × 52wk）
        → 数据分析 + 论文写作
          → 数据分析 + 论文写作
```

> 详细实施计划见 [[代码改进计划]]。三轮分别独立验证，确保每轮效果可单独评估。

## 贡献线 ①：小模型可行性验证（主线，不改代码）

### 核心问题

7B/8B 模型能否在消费级 GPU 上稳定运行长期社会模拟？原论文只在 Qwen3.5-397B 上做了。

### 实验设计

| 参数 | Baseline（原论文） | 我们的实验 |
|------|-------------------|-----------|
| 模型 | Qwen3.5-397B | Qwen3-8B (AWQ 4-bit) |
| Agent 数 | 100 | 1 → 3 → 5（阶梯测试） |
| 模拟时长 | 10 年 | 2 → 10 → 52 周（阶梯测试） |
| 周/年 | 10 | 10（保持原设） |
| 世界 | 3 个 | 1 个（apartment）起步 |

### 压力测试矩阵

| 测试 | 规模 | 时长 | 目的 | 状态 |
|------|------|:--:|------|:--:|
| T1 | 1ag × 4wk | 1h | 验证完整循环无 crash | ✅ |
| T2 | 1ag × 10wk | 2h | 单人 prompt 增长率 + 叙事多样性 | ✅ |
| T3 | 3ag × 10wk | 4h | 多 agent 交互是否触发新 bug + 社交对叙事的影响 | ✅ |
| T3A | 3ag × 10wk | 4h | 随机化 Review prompt（假设 A 验证） | ✅ |
| T3B-T4 | 3ag × 20wk | 6h | role token 2048→4096（假设 B 验证）+ 长期记忆膨胀 | ✅ |
| T5 | 5ag × 20wk | 8h | 5 agent 并发压力 + 社交网络复杂度 | ✅ |
| T6 | 5ag × 52wk | 10h | 完整一年周期，含年末 Rewards | ⬜ |

### T2/T3 阶段性发现

- **单人（T2）**：日记从 W7 开始收敛（相邻周 Jaccard 0.76+），10 周内角色未突破初始叙事状态
- **多人（T3）**：三个 agent 相互串场，Summary 更多样（~3-4 个变体），但 **Reflection 在 W3-5 冻结**——每个 agent 的"反思"部分逐字重复
- **根因假设**：2048 token 输出 + 5 周滑动摘要窗口 → 模型在 ~W4 发现局部最优模板，此后不可逆

### T3A（随机化 Review prompt）阶段性发现

**结论：假设 A ✅ 确认 — 随机化 Review prompt 完全消除了 Reflection 冻结。**

- Aaron Whitfield W10：465 条 reflection 相关短语，0 个 "I learned" 模板句
- 每个 Reflection 段落开头和内容均不同（"I felt…"、"If I could re-live…"、"My fear this week was…"、"I avoided…"）
- 叙事多样性从 T3 的「逐字重复 966 次」降到「无重复模板」
- **隐含意义**：Reflection 冻结的根本原因是 prompt 诱导（固定 3 个问题使模型在 ~W4 发现高概率模板），而非 Token 预算或模型能力不足

| 实验 | 参数变更 | 日期 | 结果 |
|------|------|------|------|
| T3A | 3ag × 10wk, `role_model_max_tokens` 4096, Review prompt 随机化（假设 A） | 2026-06-27 | ✅ 冻结消除 |

### T3B-T4（4096 token + 20wk）阶段性发现

**结论：假设 B 部分有效 — Token 增加缓解但未消除冻结。**

- Aaron Whitfield 20 周内出现 3 种 Reflection 模板（vs T3 的 1 种）
- 最高频模板出现 964 次 / 20 周 ≈ 48 次/周（vs T3 的 ~97 次/周），重复率降 ~4×
- 但三种模板各自的逐字重复仍然存在，模型依然在寻找局部最优
- **隐含意义**：Token 预算增加给了模型更多「探索空间」，但没有打破模板机制本身

| 实验 | 参数变更 | 日期 | 结果 |
|------|------|------|------|
| T3B-T4 | 3ag × 20wk, `role_model_max_tokens` 2048→4096（假设 B + T4 长期测试） | 2026-06-27 | 🟡 重复率降 4×，未根除 |

### T5（5 agent × 20wk）阶段性发现

**结论：5 agent × 20wk 并发稳定运行，社交复杂度提升。**

- 5 个活跃 agent（Aaron Whitfield, Adrian Morales, Adrian Vale, Alessandro Vieri, Alaric Voss）全部完成 20 周
- 4096 token 设置下无 crash、无上下文溢出、无 NO_RESPONSE
- 社交网络从 3 人 → 5 人，Reflection 多样性需进一步分析

| 实验 | 参数变更 | 日期 | 结果 |
|------|------|------|------|
| T5 | 5ag × 20wk, `role_model_max_tokens` 4096 | 2026-06-28 | ✅ 稳定通过 |

### 综合结论（T1-T5 完成后）

1. **根因确认**：Reflection 冻结的主因是 **Prompt 诱导**（假设 A），随机化即可消除
2. **Token 效果**：4096 token 降低了模板重复率但未根除（假设 B 部分有效）
3. **稳定性确认**：8B 模型在 5ag × 20wk 范围内稳定运行无 crash
4. **下一步**：随机化 Review prompt 应作为标准配置（零成本改进）；分层记忆压缩（假设 C，③）和每天时间分段（④）的优先级可重新评估——如果随机 prompt 已经解决了冻结，③+④ 的价值更多在于「长期记忆多样性」而非「解决冻结」

### 评估指标

- 模拟稳定性：是否出现 crash、上下文溢出、NO_RESPONSE
- 叙事多样性：相邻周日记 Jaccard 词重叠率
- 社交互动质量：是否有跨 agent 互动、关系变化
- Token 消耗效率：prompt 增长率、缓存命中率

### 可能的两种结果

1. **小模型可行** → 论证"资源需求从 H100 集群降到消费级 GPU"
2. **小模型不行** → 分析"哪些维度需要至少 XX 参数才能涌现"（同样可发表）

## 贡献线 ③：系统记忆（agent 不写日记，God 三层压缩）（第一个改代码）

### 核心问题

原论文的记忆是 append-only，5 周滑动窗口外的信息永久丢失。T3 实验证实：模型在 W3-5（恰好是 5 周窗口边界）找到高概率模板并冻结 Reflection。

论文作者承认："Memory growth is a major computational bottleneck."

### 改进方案

仿人记忆的遗忘曲线：

| 时间距离 | 存储精度 | 实现方式 |
|---------|---------|---------|
| 近 5 周 | 完整日记原文 | 保持现有 `recent_summary_weeks: 5` |
| 5-20 周 | ~200 字要点 | week 6 到来时自动压缩 week 1 的完整日记 |
| 20 周+ | ~50 字里程碑 | 只保留重大事件（关系变化、职业变化、重大成就） |

### 需要改的代码

| 文件 | 改动 | 行数估计 |
|------|------|:--:|
| `src/agents/data_manager.py` | `read_weekly_summaries()` 改成读三层；新增压缩方法 | ~80 行 |
| `src/agents/role_agent.py` | prompt 构建段（L1386-1397）注入三层记忆 | ~30 行 |
| `src/agents/prompts.py` | 加分层记忆的 system prompt 描述 | ~20 行 |

### 预期效果

模型在 weekly review 时能看到"5 周前发生了什么（要点）"和"20 周前的重大事件（里程碑）"，而非完全遗忘。预期 Reflection 冻结的起始周从 W3-5 推迟到 W10+。

## 贡献线 ④：24h 时间下钻（每天 4 时段，自主作息）

### 核心问题

原论文的时间粒度是"周"：agent 每周做一个计划，然后 n_day=5 天每天执行相同的活动。这导致行为模式过于重复——每天醒来做同一件事。

加上每天时间分段后，agent 的每周 5 天 × 3 时段（早/中/晚）= 每天有不同的作息节奏。

### 改进方案

| 当前（周粒度） | 改进后（天 × 时段粒度） |
|---------------|---------------------|
| 每周一次 Plan | 每天做一次短期计划 |
| 每天 1 个活动（重复 5 天） | 每天 3 个时段（早/中/晚），各做不同的事 |
| prompt 描述"本周做什么" | prompt 描述"明天每个时段做什么" |

### 需要改的代码

| 文件 | 改动 | 行数估计 |
|------|------|:--:|
| `src/world/clock.py` | 时间粒度从"周"下钻到"天 × 时段" | ~30 行 |
| `src/world/scheduling.py` | 活动安排从"本周列表"变成"每天时段表" | ~40 行 |
| `src/agents/role_agent.py` | Plan 阶段从"周计划"改成"明天时间表" | ~30 行 |
| `src/agents/prompts.py` | 重写 Plan prompt，加入时段概念 | ~20 行 |

### 预期效果

agent 有了自然的"作息节奏"——上午工作、下午社交、晚上休息——行为多样性增加。和③配合：记忆记得更久（③）+ 每天有变化（④）→ Reflection 冻结问题应该大幅改善。

## 贡献线 ⑤：健康系统（身心指标 + 极端行为）

### 核心问题

原论文的"生命奖励"完全由客观指标计算（社交 PageRank + 经济变化 + 满足度历史），与角色主观感受脱钩。

论文作者承认："Reward not fully aligned with human well-being; all feedback from AI models, not humans."

### 改进方案

在 Review 阶段增加自评：

```
角色在当前周的 Review 中，额外输出：
<self_assessment>
  happiness: 72     # 0-100 主观幸福感
  stress: 35        # 0-100 压力值
  autonomy: 60      # 0-100 自主感
</self_assessment>
```

将这个自评与系统计算的 reward 做差值校准：
- 如果客观奖励高但自评低 → 信号矛盾，降低该样本权重
- 如果客观奖励低但自评高 → 重新审视 reward 公式

### 需要改的代码

| 文件 | 改动 | 行数估计 |
|------|------|:--:|
| `src/agents/role_agent.py` | Review prompt 加 `<self_assessment>` 输出要求 | ~15 行 |
| `src/world/reward.py` | `compute_subjective_rewards()` 解析自评，做差值校准 | ~30 行 |
| `config.json` | 加 `self_assess_weight` 等参数 | ~5 行 |
